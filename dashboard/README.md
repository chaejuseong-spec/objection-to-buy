# 대시보드 (Next.js)

리포트 PDF를 웹에서 올리고, 비용을 확인한 뒤 AI 반대신문을 시작하고, 결과를 보는 작업대.
평가나 계산은 하지 않는다. 분석은 파이썬 에이전트(`tribunal`)가 하고, 이 화면은 그 결과를 보여주기만 한다.

## 처음 한 번만

1. Node.js LTS와 파이썬 3.11 이상을 설치한다.
2. 프로젝트 맨 위 폴더에서 `pip install -r requirements.txt`, 이 `dashboard` 폴더에서 `npm install`.
3. 프로젝트 맨 위 폴더의 `.env` 에 `GEMINI_API_KEY=` 를 넣는다.

## 띄우기

```
npm run dev
```

브라우저에서 http://localhost:3000 을 연다. 바탕화면 아이콘이 같은 일을 한다.

## 쓰는 순서

1. 왼쪽 위 **새 리포트 올리기**를 누르거나, 화면 아무 곳에나 PDF를 끌어다 놓는다. 올리기만 해서는 비용이 들지 않는다.
2. 쪽수, AI 호출 수, 최대 사용량을 확인하고 **비용을 확인했고, 분석을 시작합니다**를 누른다.
3. 진행 단계가 보인다. 창을 닫아도 분석은 계속되고, 다시 열면 이어서 보인다.
4. 끝나면 탭으로 결과를 본다: 리포트 요약, 수치와 도표, 원문에서 보기(PDF 위 판정 색), 반대신문 과정, 나의 판단 기록, 채점.

실패하면 이유와 **다시 시도** 단추가 나온다. 다시 시도하면 끝난 단계(`run/steps/`)는 건너뛰고 멈춘 곳부터 이어서 한다.
Google 서버 혼잡(503, 504)은 프로그램이 알아서 기다렸다 최대 3번 다시 부르고, 그래도 안 되면 `config.yaml`의 `fallback_models`로 바꿔 본다.

## 파일이 어디에 쌓이나

프로젝트 맨 위의 `library/<id>/` (깃에 올리지 않음)

| 파일 | 내용 |
| --- | --- |
| `report.pdf` | 올린 원문 |
| `meta.json` | 파일 이름, 올린 시각, 비용 미리보기 |
| `run/` | 파이썬 에이전트의 결과 (`result.json`, `평가기록지.md` 등) |
| `done.json` | 성공 여부와 오류 문구 |
| `log.txt` | 파이썬 출력. 문제가 생기면 여기를 본다 |
| `grading.json` | 채점 탭에서 체크한 내용 |

채점 정답지는 `eval/answers/<PDF 지문>.json`(같은 PDF면 다시 올려도 같은 정답지), 기록한 점수는 `eval/scores.jsonl`에 쌓인다. 둘 다 깃에 올리지 않는다.

처음 열 때 기존 `data/result.json`(데모)을 보관함 첫 항목으로 복사한다. 원본은 건드리지 않는다.
나의 판단 기록과 체크 표시는 브라우저(localStorage)에만 저장된다.

## 구조

| 위치 | 내용 |
| --- | --- |
| `app/api/reports/` | 목록·올리기, 상태·결과·지우기, 분석 시작(`run`), 원문(`pdf`), 평가기록지(`record`) |
| `lib/server/library.ts` | 보관함 폴더 관리, 파이썬 실행(`python -m tribunal.web`) |
| `components/workspace/` | 화면. `Workspace.tsx` 가 상태를 모두 관리 |
| `components/workspace/workspace.module.css` | 디자인 토큰과 모든 스타일 |

AI 회사는 `lib/server/library.ts` 의 `PROVIDER` 한 곳에서 정한다(지금은 gemini).

## 디자인 규칙

- 색은 판정에만 쓴다. 빨강 = 수정·불일치, 주황 = 확인 필요, 초록 = 유지·일치. 그 밖의 강조는 잉크색.
- 카드 박스를 늘어놓지 않는다. 구획은 얇은 선(1px)과 굵은 선(2px, 섹션 시작)으로 나눈다.
- 주장은 "C-1" 같은 코드 대신 번호(1, 2, 3)로 쓴다.
- 문장으로 쓴다. "A · B · C" 식 메타 문구를 쓰지 않는다.
