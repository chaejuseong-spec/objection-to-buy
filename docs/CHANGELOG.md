## v1.0 — 첫 공개본 (2026-11-18)

v0.1 ~ v0.7에서 만든 내용을 묶은 첫 공개 버전입니다.

**할 수 있는 것**
- 기업분석 리포트 PDF 한 편을 넣으면 추출 → 코드 검증 → 리스크 검토자 → 배심원 5명 → 코드 판정 → 판사를 거쳐 평가 결과를 만듭니다.
- 리포트 숫자를 다시 계산하고 OpenDART · KRX · ECOS · KOSIS 공식 데이터와 대조합니다.
- 대시보드에서 원문 위 표시, 이의와 표결 과정, 근거 종합표, 나의 판단 기록, 채점을 봅니다.
- 오류를 일부러 넣은 사본으로 검증 품질(탐지율, 오탐)을 잽니다.

**공개를 위해 정리한 것**
- 데모를 **교육·시연용 가상 리포트**("한빛소재(가상)", 5쪽)로 바꿨습니다. 남이 쓴 리포트의 원문·분석 결과는 저장소에 넣지 않습니다. 가상 리포트에는 도구가 잡아낼 약점(뜻이 다른 숫자의 혼용, 다시 계산되지 않는 목표주가, 쪽마다 다른 일정, 근거 없는 단정)을 일부러 심었습니다.
- README를 처음 보는 사람이 구조를 바로 이해할 수 있게 도식 중심으로 다시 썼습니다.

## v0.7 — 원문 전체 읽기, 배심원 개편, 비용 최적화 (2026-11-16 ~ 18)

**구조**
- 리스크 검토자와 배심원이 요약본뿐 아니라 **리포트 원문 전체**를 읽습니다. 이의에는 원문 인용을 반드시 붙이고, 코드가 인용을 원문과 글자 단위로 대조합니다.
- 리포트의 표를 옮겨 코드가 검산합니다.
- AI 모델을 Claude Opus 5.5로 바꿨습니다.

**표 세는 방식 변경**
- '확인 불가'는 "내 분야로는 판단하기 어렵다"는 표로 보고, 판정을 막지 않습니다.
- 판단한 표(타당·과장)가 3표 이상일 때 그 과반으로 판정하고, 3표 미만이면 사람이 확인하도록 '확인 필요'로 둡니다.

**배심원 개편과 업종 모듈**
- 다섯 배심원이 같은 이의를 서로 다른 **각도**로 보도록 지시서를 다시 썼습니다. 표를 일부러 갈라 놓는 것이 아니라, 판단의 근거가 겹치지 않게 하는 것이 목표입니다.
  - 회계사: 서로 다른 기준의 숫자를 섞어 썼는가
  - 산업 전문가: 사업 가정이 실적 전망으로 이어지는가
  - 공매도 투자자: 가정이 틀리면 손실이 어떤 경로로 번지는가
  - 통계학자: 기간·표본 선택과 모델이 튼튼한가
  - 행동경제학자: 주장의 강도가 근거의 강도보다 세지 않은가
- 배심원은 '내 분야에서 본 점'과 '판단 이유'를 나눠 씁니다. 판단 이유는 표의 방향으로 시작하고 근거 번호로 끝납니다.
- 업종(보험, 은행, 증권, 제조업, 건설, 소비재, 소프트웨어, 지주회사)은 코드가 정하고, 배심원마다 그 업종의 **점검 모듈**을 붙입니다.

**지시서 1차 개편**
- 리스크 검토자, 판사, 추출 담당, 모든 역할 공통 규칙, 배심원 공통 규칙을 다시 썼습니다.
- **당시 기준 검증** 원칙을 넣었습니다. 리포트 발행 시점에 알 수 있었던 정보로만 판단하고, 나중에 전망이 빗나갔다는 이유로 당시 분석을 틀렸다고 하지 않습니다.
- 지시서의 예시는 모두 분석 대상과 다른 업종의 가상 사례로 바꿨습니다.

**비용 최적화**
- 역할마다 모델을 따로 고를 수 있게 했습니다. 가장 어려운 리스크 검토자는 Opus 5.5, 나머지는 절반 가격인 Sonnet 5.5를 씁니다.
- 실제로 쓴 토큰과 비용을 역할별로 `usage.json`에 기록합니다.

**고친 것**
- 리스크 검토자의 답이 출력 한도에 걸려 잘리던 문제: 한도를 따로 늘리고, 답이 없으면 '문제 없음'처럼 보이지 않게 멈춥니다.
- KRX 대조에서 우선주를 보통주 시세와 비교하던 오탐, 회사 이름 뒤의 날짜·'기준주가'를 이름으로 읽던 오탐을 고쳤습니다.

## v0.6 — KOSIS 대조, 기준 점수 측정과 개선 (2026-11-15)

**측정 결과가 가장 크게 바뀐 버전입니다.**

- 통계청 KOSIS 산업 통계 대조 추가
  - 같은 대상·같은 기간·같은 단위의 값을 찾을 때만 "일치"로 봅니다. 찾지 못하면 "불일치"로 단정하지 않고 "검증 불가"로 둡니다.
  - 개발 중 "라면"을 검색하다 "산소" 통계와 값이 맞아버리는 오탐이 나왔습니다. 대상 이름 확인과 흔한 말 걸러내기를 넣어 막았습니다.
- 기준 점수 측정 후 고친 것
  - 연도가 적히지 않은 재무 숫자는 직전 결산연도로 보고 대조합니다. 이렇게 짐작한 경우 불일치가 나와도 "확인 필요"까지만 올립니다.
  - AI가 검증 식에 숫자를 직접 써 넣은 경우(지어낸 숫자) 그 식을 버립니다.

| 측정 (실제 기업분석 리포트 1편, 넣은 숫자 오류 10개) | 잡은 오류 | 탐지율 (검증 수단 있는 것) | 오탐 |
|---|---|---|---|
| 고치기 전 | 2 | 29% | 1 |
| 고친 뒤 | 6 | 71% | 0 |

고친 뒤 재측정은 저장해 둔 추출 결과를 다시 써서 AI 호출 0회로 했습니다.

## v0.5 — 근거 종합표와 판정 통합 (2026-11-15)

- 고정 산식 검산: AI가 검증 식을 만들지 않아도 상승여력, PER, PBR, 영업이익률 등 12개 산식은 코드가 항상 검산합니다.
- DART 배당 공시 대조, 끝난 분석에 산식 검산 다시 적용
- 근거 종합표와 배심원 의견 갈림 표시: 주장마다 근거 숫자가 사실·계산·추정·가정 중 무엇이고, 무엇으로 확인됐는지 정리합니다.
- 공식 데이터 불일치를 주장 판정에 반영: 배심원 판정과 숫자 검증 중 더 엄한 쪽을 씁니다. 배심원이 놓쳐도 공시와 다른 숫자에 기댄 주장은 "수정"이 됩니다.
- 근거 종합표를 화면 오른쪽 패널에 표시
- 나의 판단 기록 개편: AI 결과를 보기 **전**과 **후**의 행동을 따로 남기고, 판단이 바뀌었는지 표시합니다.
- 채점 탭에 자동 오류 삽입 테스트 결과 표시
- DART 분기·반기 실적 대조: 4분기는 연간 값에서 3분기 누적을 빼 계산합니다.
- 통과한 곳도 초록으로 칠하기: 기본은 숨기고, 켜면 문제없는 주장과 일치한 숫자도 보입니다.

## v0.4 — 품질 측정 도구와 신뢰성 수정 (2026-11-14 ~ 15)

- "1조 8,367억 원"처럼 값에 조·억이 들어 있는데 단위 칸 "조 원"과 겹쳐 두 번 곱하던 문제 수정
- 검증 품질 평가 도구 추가: 일치로 확인된 숫자를 8~13% 바꾼 PDF 사본을 만들어, 에이전트가 몇 개를 잡는지 자동으로 잽니다.
- AI 답 형식과 사용 한도 대응 보강
- 하루 사용 한도는 다시 시도하지 않고 바로 알리기: 무료 등급의 하루 한도는 기다려도 풀리지 않아, 재시도에 시간을 쓰지 않고 남은 시간을 안내합니다.
- 연결/별도 표기가 없는 숫자의 사각지대 수정: 이전에는 표기가 없으면 틀린 숫자도 항상 "검증 불가"로 빠졌습니다. 리포트 안의 다른 표기와 값의 가까움으로 기준을 정하도록 바꿨습니다.

## v0.3 — 공식 데이터 대조 (2026-11-14)

- OpenDART 공시 재무제표 대조: 연결/별도, 단위, 연도를 구분합니다. 리포트 작성 이후에 나온 공시와만 다르면 불일치로 보지 않습니다.
- KRX 시장 데이터 대조, 공식 데이터 대조 공통 모듈: 모든 공식 대조 결과가 같은 형식(상태, 공식 값, 출처, 조회 시각, 작성 당시 공개 여부)을 씁니다.
- 한국은행 ECOS 거시 통계 대조: 환율, 금리, 물가
- 리포트 입력 지시서 보강: 바깥 자료와 대조할 거시·산업·시장 숫자도 옮기도록 했습니다.

원칙: 인증키는 `.env`에서만 읽고, 기록하는 주소에서는 키를 `{인증키}`로 가립니다.

## v0.2 — 숫자 검증과 형식 안정화 (2026-11-14)

- 숫자 검증과 AI 답 형식 오류 수정: AI가 "타당함"처럼 정해진 값을 조금 바꿔 쓰면 원래 값으로 되돌리고, 틀린 항목만 빼고 나머지 답은 살립니다.
- 채점 탭 추가, 단위 중복 표시 수정: 사람이 쓴 정답지와 에이전트 결과를 비교하는 화면입니다. "54.7%%" 같은 표시 오류도 고쳤습니다.

## v0.1 — 첫 완성 (2026-11-14)

- 반대신문 파이프라인: 추출 담당 → 원문 대조 → 리스크 검토자 → 배심원 5명 → 코드 판정 → 판사
- 웹 작업대: PDF 올리기, 보관함, 리포트 요약 / 수치와 도표 / 원문에서 보기 / 반대신문 과정 / 나의 판단 기록 탭, PDF 형광펜, 첫 소개 화면, 설명서
- 이름과 화면 다듬기
  - "검사"는 역할이 직관적이지 않아 **"리스크 검토자"**로 바꿨습니다.
  - 탭 이름과 순서를 사용 흐름에 맞게 정했습니다.
  - 브랜드명은 "매수에 이의 있습니다!"입니다.
- Gemini 서버 오류(503) 대응
  - 새 모델이 계속 503·504를 내서 안정적인 모델로 바꿨습니다.
  - 대기 시간을 두 배씩 늘리는 재시도와 예비 모델을 넣었습니다.
  - 끝난 단계는 저장해 다시 시도할 때 이어서 하도록 했습니다.
